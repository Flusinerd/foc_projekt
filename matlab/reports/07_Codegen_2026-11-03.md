### Abweichung 1: DeviceID F28388D statt F28386D

Der Code wird für F28388D gebaut (Defines, Linker, `f28388D.ccxml`). F28386D und F28388D gehören zur selben F2838x-Familie mit gleichem CPU1-Teil. Ob das Blockset R2023a F28386D als Auswahl anbietet und ob Speicher, Linkerdatei oder Peripherie (z. B. CM, EtherCAT) sich für diese Firmware unterscheiden, habe ich nicht geprüft. Für reine Codegenerierung ist das unkritisch, vor dem Flashen (Schritt 8) ist es zu klären.

### Abweichung 2: interner 10-MHz-Oszillator statt externer 25 MHz

Die Firmware stellt die PLL aus INTOSC2 (10 MHz) auf 200 MHz ein und nutzt den externen 25-MHz-Oszillator der Platine nicht. Die CPU läuft damit trotzdem mit 200 MHz, aber mit der Toleranz des internen Oszillators (laut Datenblatt einige Prozent). Das betrifft PWM-Frequenz, ADC-Abtastung, SCI-Baudrate (SCI_A 5 MBd) und CAN-Bittiming. Diese Einstellung stammt aus dem Altmodell der MA und lief laut MA. Vor Schritt 8 entscheiden, ob für die Erstinbetriebnahme (Stand P1a, „lief laut MA“) bewusst beibehalten oder auf `UseInternalOsc = 0`, `OSCCLK = 25` umgestellt wird (dann PLL-Werte neu, Auto-PLL). Das ist eine Modelländerung per Skript und ein eigener Schritt.

### Abweichung 3: keine Totzeit im ePWM, Komplementarität nur über den DRV8300DI

Die Annahme aus der Diagnose (`05_P1b_Diagnose`, „`DBedgeDelay = Positive`, nur RED an A“) trifft im generierten Code **nicht** zu. `DBCTL.OUT_MODE = 0` heißt: Das Totzeit-Modul ist für **A und B** umgangen, und `DBRED = 0` würde ohnehin keine Verzögerung bringen. Damit gilt für die Ansteuerung:

- GH*x* ← INH*x* = ePWM*x*A, GL*x* ← NOT(INL*x*) = NOT(ePWM*x*B) (DRV8300**DI**: INL invertiert).
- Mit CMPB = CMPA und gleichen Aktionen gilt B = A, also GL = NOT(GH): **komplementär** ✔.
- Die einzige Totzeit ist die feste Totzeit des DRV8300DI (200 ns, mit Querstromsperre laut SLVSFG5). Das ist bei diesem Treiber ausreichend und so vorgesehen. Im MCU gibt es keine zusätzliche Totzeit.
- Freemode (WA = 0 → CMPA = 0, WB = 1 → CMPB = TBPRD): Gewollt ist A dauerhaft low und B dauerhaft high, also GH = GL = 0, beide Schalter aus. Welchen Pegel die AQ-Logik im Up-Down-Modus bei CMPA = 0 bzw. CMPB = TBPRD tatsächlich ausgibt (Ereignisse genau an den Umkehrpunkten), hängt von den Sonderfällen im TRM (SPRUII0, Abschnitt Action Qualifier, „CMPx = 0 / = TBPRD“) ab. Das habe ich nicht abschließend aus dem Code ableiten können. **Vor dem ersten Lauf in Schritt 8 bei kleiner PVDD mit dem Oszilloskop an GHA/GLA im Freemode messen.**

Die Kernaussage für Schritt 8 bleibt richtig: Die Phasen werden komplementär angesteuert. Begründet ist sie jetzt durch den Code (B = A, kein Totzeit-Modul) und die Treiber-Variante DI, nicht mehr durch „RED nur an A“.

### Abtastzeitpunkt

SOCA bei CTR = PRD. Mit CAU = Clear und CAD = Set ist A zwischen CMPA (aufwärts) und CMPA (abwärts) low, also auch bei CTR = PRD. Die Low-Side leitet, der Shunt misst. Das bestätigt die Voraussetzung aus `05_P1b_Diagnose` (Zeile „ADC-Trigger SOCA“).

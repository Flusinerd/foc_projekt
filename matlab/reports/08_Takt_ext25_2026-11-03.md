# app_speed: Umstellung auf den externen 25-MHz-Oszillator (2026-11-03)

Anlass: CAN-Test (`08_CAN_Test_2026-11-03.md`). Mit dem internen Oszillator INTOSC2 (Taktquelle der MA-Firmware) gibt es bei 1 Mbit/s nur Bit- und Formfehler; mit dem externen 25-MHz-Oszillator der Platine läuft CAN fehlerfrei. Abweichung 2 aus Schritt 7. Entscheidung des Menschen: umstellen.

## Änderung (`tools/foc_clock_ext25.m`, Log `08_clock_ext25.log`)

| | vorher (MA) | nachher |
|---|---|---|
| Taktquelle | INTOSC2 (`UseInternalOsc = 1`) | **XTAL, externer Oszillator** (`UseInternalOsc = 0`) |
| OSCCLK | '10' MHz | **'25' MHz** |
| PLL | ×40, /2 | **×16, /2** |
| CPU | 200 MHz | 200 MHz |
| erzeugter Code | `MW_InitSysPll(INT_OSC2,40,0,0,1,…)` | `MW_InitSysPll(XTAL_OSC,16,0,0,1,…)` |

Die Werte im Clocking-Block sind Zeichenketten. `focLib.slx` und das Altmodell sind unverändert.

## Nachweise

| Prüfung | Ergebnis |
|---|---|
| `slbuild('app_speed')` (Build action im Speicher „Build“, kein Laden) | erfolgreich, keine Compilerwarnung; Modell hashgleich (nicht gespeichert) |
| PLL-Aufruf im Code | `MW_InitSysPll(XTAL_OSC,16,0,0,1,SYSCTL_DCC_BASE0)` ✔ |
| `foc_check_equivalence` (legacy, Regler im Speicher auf P1a) | alle Abweichungen 0 (CoderTargetData wirkt nur auf die Codegenerierung) |
| externer Takt auf der Hardware | mit `foc_can_probe` (gleicher PLL-Aufruf) bestätigt: PLL rastet ein (LED blinkt), CAN fehlerfrei |

## Hinweise

- Das Blockset initialisiert den externen Takt im Quarz-Modus (`XTAL_OSC`), nicht als Single-Ended-Eingang. Auf dieser Platine funktioniert das; bei einer neuen Platinenrevision prüfen.
- Für Schritt 8 (Hardwarelauf): Die PWM-Frequenz (20 kHz) und die Abtastzeiten sind jetzt an den genauen externen Takt gebunden.
- Offen bleibt aus Schritt 7: DeviceID F28388D statt F28386D.
